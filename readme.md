This is an application used to lay out photo books automatically and allowing for tweaking as well.

Here is the process.

1. A folder of photos will be provided. They will be in different formats. jpg, heic, webp, png, etc.
2. A journey in Word may be provided that has dated entires to be interleaved with the pictures.
3. Each book will contain one year
4. Each chapter should stand alone and be editable as a unit.
5. Template pages should be created that support images, and text. The journal text for a day should all be together. The pictures should support captions either below the images in some cases or over the images as needed. For example a full-bleed image might need overlay text for the caption. Most images won't have captions, but some will.
6. The photos for a month should be displayed in some type of a UI that will allow for inspection and reordering. It should support changing the date on a photo which might move it to a different month or even out of the year that is being worked. It should also allow basic editing like brightness and contrast to fix the image and cropping. Some advanced features to adjust the characteristics of the image would be good here.
7. The app should do an initial layout of a month with te pictures in chronological order.
8. Pages should support editing as either a single page or a full two page spread.
9. Then the user should be able to move pictures around by dragging and dropping. Pictures should be automatically cropped to the area assigned. The user should be able to move the picture around in the area to realign the cropped region based on the relative size of the container. The user should also be able to zoom a picture. If the image is too 'small' for the space because the user made the image smaller than the space in one dimension then the background should just show through.
10. The user should be able to select a new page layout for a page. If the page has fewer images, the image should be put into a not laid out bin that the user can see on either the bottom or the side (selectable by the user).
11. The user should be able to do advanced editing on images that are either place in a layout or in the unused images bin. Color adjustments, etc.
12. If the user selects a layout with additional images, the user should be able to select images from either the unused bin or the future bin to place there.
13. The bin should show the unused images or the upcoming images so that images that are on subsequent pages can be easily moved to the current page.
14. Image locations that do not have images inserted should be flagged to indicate that something is missing.
15. The user should be able to make per page modifications to the layout for only that page. They should be able to add/change/delete an image container specifically location and size. Add additional image containers and or remove text containers.
16. There should be a button that will automatically lay out the rest of the chapter once changes are made. This should warn the user that all pages past this point will be changed. There should also be an option to automatically lay out all the images for the day or insert pages for the images in the unplaced bin. 
17. The user should be able to remove an image from the unplaced bin and that image will no longer be part of the photo book. For example if two images that were too much the same were chosen by accident. 
18. A few layouts should support full page spreads of a photo or photos. This should not be the norm, but should be supported.
19. Different page sizes should be supported.
20. There should be many page layout templates to choose from. They should have different size photo options with up to 8 photos per page. The image placeholder locations should have different aspect ratios and be of different sizes. The layouts should use most of the space on a page, but not always. It should support reflections to use it on a left or right page. If there is no journal entry for the page, the text area will be left blank and this ia a good way to provide negative space. Not all layouts need a text area.
21. The background of the pages should be solid black for now, but this will be changed in the future allowing for images to be provided for the page background to support more of a scrapbook look. For now the emphasis is getting the images and text laid out mostly automatically.
22. There should be consideration for how the pages will look when they are a two page spread however, pages should be editable and the layouts changeable independently. This means there might be two page layouts that are matched between right and left pages. This could be deferred.
23. Styles should be supported so that if borders are added to images this can be done to all images on all pages. Font sizes and colors should be changed globally as well. Journal and caption text should be able to be different sizes.
24. Each month should have a 'title' page that indicates the name of the month. This page should be a layout that has some picture options. The month name could overlap the image. It should be in a larger font than the journal or caption text.
25. The image placement engine should determine the interesting area of a picture and place it in the placeholder location in a layout keeping the important focus area(s) visible. This should be automatic and feel like it is just doing the right thing. This will allow the engine to crop photos to a different aspect ratio and keep the important parts visible. Ideally this is done in a pre-processing step and the user should be able to see there when looking at all the photos (for the book or month). The user should be able to change the focus areas so that the automatic layout will work better. 
26. There should also be a determining of the goodness of an image compared to other images. This should determine the relative size of the image container it gets put into. The user should be able to change this promoting or demoting the image. 
27. Ideally all the image detection algorithms above would be local, but if better results can be gotten by using AI resources in Azure then I want to do that. That automatic layout being awesome is the most important page. Edits should really be tweaks.
28. Each day doesn't need a page of it's own. If there are 2-3 days that have 2-3 images and some journal entries these can be combined onto a single page. I know this is a lot, but I want to make something that will allow me to create memory books for our family that document our kid's childhood and our story as a family.
