# 15 — Glossary

Every domain term of art used across the doc set, alphabetized, with a 1–3 sentence definition
and a link to the doc that owns the full specification. Convention (used by all docs): glossary
terms are capitalized on first use per doc; when a definition here disagrees with an owning doc,
the owning doc wins and this file gets fixed. Requirements are cited as R1–R28, the numbered
items in the repo [readme.md](../readme.md).

Related docs: [README.md](README.md) · [01-vision-and-principles.md](01-vision-and-principles.md)
· [03-domain-model.md](03-domain-model.md)

## Terms

| Term | Definition | Owning doc |
|------|------------|------------|
| AdjustmentStack | The ordered, parametric, non-destructive list of image edits (brightness, contrast, color, …) stored on a Photo and applied at render time by Magick.NET (R11). The original file is never modified. | [03-domain-model.md](03-domain-model.md) (entity), [09-editor-ux.md](09-editor-ux.md) (editing UI) |
| Amber flag | The visual marker on an empty ImageSlot indicating a photo is missing from the layout (R14). | [09-editor-ux.md](09-editor-ux.md) |
| Atomic write | Persistence rule: write to a temp file, then rename over the target, so a crash never leaves a half-written JSON file. | [04-project-format-and-storage.md](04-project-format-and-storage.md) |
| Autosave | The project saves every 30 s and after major operations, keeping a rolling `.bak` alongside each file. | [04-project-format-and-storage.md](04-project-format-and-storage.md) |
| AzureVisionAnalyzer | The optional, opt-in (per-book) `IImageAnalyzer` implementation backed by Azure AI Vision (R27); a drop-in alternative to LocalOnnxAnalyzer behind the same interface. | [06-image-analysis.md](06-image-analysis.md) |
| Bleed | The 0.125 in extension beyond Trim on each outer edge that the printer cuts through; the single-page bleed box is 11.25 × 8.75 in. | [12-pdf-export.md](12-pdf-export.md) |
| Book | The root entity: one calendar year (R3) with its Chapters, Style, page size, Print Profile reference, and Seed; persisted in `book.json`. | [03-domain-model.md](03-domain-model.md) |
| Caption policy | Per-ImageSlot setting `none \| below \| overlay` controlling where a photo's caption renders; full-bleed photos use overlay captions on a scrim (R5). | [07-layout-template-system.md](07-layout-template-system.md) |
| Chapter | One month of the Book, standing alone and editable as a unit (R4); persisted as `chapters/YYYY-MM.json`. | [03-domain-model.md](03-domain-model.md) |
| Cover scale (`coverScale`) | `max(slotW/imgW, slotH/imgH)`: the scale at which an image exactly covers its Slot. CropState's `zoom` multiplies it to give the effective scale. | [03-domain-model.md](03-domain-model.md) |
| CropState | `{ zoom, offsetX, offsetY }` — the one crop model shared verbatim by the engine and the editor. `zoom = 1.0` is the minimal-crop cover fit; `zoom < 1` letterboxes so the page background shows through (R9); offsets pan in slot-width/height units, clamped while `zoom ≥ 1`. | [03-domain-model.md](03-domain-model.md) |
| Date chain | The precedence for a Photo's date: EXIF `DateTimeOriginal` → Graph `photo.takenDateTime` → file mtime (last resort, which sets `dateUncertain`). | [05-ingestion-and-photo-sources.md](05-ingestion-and-photo-sources.md) |
| `dateUncertain` | Photo flag set when the date came from file mtime; surfaced in the UI (R6) and reported by Preflight. | [05-ingestion-and-photo-sources.md](05-ingestion-and-photo-sources.md) |
| Day Group | The consecutive photos and journal text of one calendar day — the unit the engine partitions into pages; 2–3 sparse days can merge onto a single page (R28). | [08-auto-layout-engine.md](08-auto-layout-engine.md) |
| Demand Model | Engine phase that estimates how much page area each Day Group wants, from photo count, Tiers, and journal text length. | [08-auto-layout-engine.md](08-auto-layout-engine.md) |
| Detached (page state) | A Page whose Template was hand-edited (containers added/moved/removed, R15) into an inline template snapshot; the library Template itself is never mutated. | [03-domain-model.md](03-domain-model.md) |
| DP page partitioning | The dynamic-programming engine phase that splits the ordered Day Group sequence into pages — merging sparse days (R28) and splitting photo-heavy days across pages. | [08-auto-layout-engine.md](08-auto-layout-engine.md) |
| Excluded photo | A catalog entry with `excluded: true`: removed from the book but never from disk, and kept excluded across re-scans and re-syncs (R17). | [03-domain-model.md](03-domain-model.md) |
| Focus Region | `{ rect, weight, kind, personName? }` on a Photo marking what must stay visible when cropping (R25). Kinds fuse with priority `user > person > face > saliency`; the user can add and edit them. | [06-image-analysis.md](06-image-analysis.md) |
| Full-bleed | Template kind whose photo extends through Trim to the Bleed edge (R18); captions become overlays (R5). | [07-layout-template-system.md](07-layout-template-system.md) |
| Golden layout test | A checked-in test that runs the engine over a fixed fixture Chapter and asserts the whole `LayoutResult` — templates, slot→photo assignment, CropStates — against a stored expectation. It is the mechanism that makes "same inputs + same Seed ⇒ same book" enforceable rather than aspirational. | [13-testing-strategy.md](13-testing-strategy.md) |
| Gutter | The binding edge of a Spread: the inner edge of each Page, where the two facing Pages meet at the Spread centerline. Templates are authored as right pages with the gutter at `x = 0` (see Mirroring); content near it is governed by the Gutter caution zone. | [12-pdf-export.md](12-pdf-export.md) |
| Gutter caution zone | The 0.5 in band either side of the Spread centerline where faces and text must not sit; full-Spread photos accept center loss. | [12-pdf-export.md](12-pdf-export.md) |
| Hungarian assignment | Engine phase that assigns photos to ImageSlots by solving the assignment problem (Hungarian algorithm), minimizing crop loss plus Tier mismatch. | [08-auto-layout-engine.md](08-auto-layout-engine.md) |
| IImageAnalyzer | The pluggable analysis interface producing Focus Regions and QualityScores. Implementations: LocalOnnxAnalyzer (default) and AzureVisionAnalyzer (optional, R27). | [06-image-analysis.md](06-image-analysis.md) |
| ImageSlot | The photo-holding kind of Slot: `{ id, rect, aspect, aspectTolerance, tierAffinity, captionPolicy, bleed, spanId? }`. Exactly one photo cover-fills it through a CropState; an ImageSlot with no Placement is empty and amber-flagged (R14). | [07-layout-template-system.md](07-layout-template-system.md) |
| Import Report | The UI report produced by journal parsing, listing unmatched or ambiguously dated entries for the user to resolve. | [11-journal-ingestion.md](11-journal-ingestion.md) |
| Job queue | The `System.Threading.Channels` background queue (one lane per work kind) that runs decode, thumbnailing, analysis, layout, and export off the UI thread. Results are applied back on the UI thread through the single-writer command pipeline. | [02-architecture.md](02-architecture.md) |
| JournalEntry | One dated block of text parsed from the Word journal (.docx via OpenXML), interleaved with photos by date (R2); a day's text is atomic (R5). | [11-journal-ingestion.md](11-journal-ingestion.md) |
| LocalOnnxAnalyzer | The default `IImageAnalyzer`: ONNX Runtime models (YuNet, U2-Netp, NIMA) plus classical sharpness/exposure metrics, fully offline. | [06-image-analysis.md](06-image-analysis.md) |
| Mirrorable | Template flag: the layout may be auto-mirrored horizontally to serve as either a left or a right page (R20). | [07-layout-template-system.md](07-layout-template-system.md) |
| Mirroring | The load-time transform `mirror(rect) = { x: 1 − x − w, y, w, h }` that turns a `mirrorable` Template — always authored as a right page — into its left-page variant (R20). Slot ids, aspects, tier affinities, caption policies, and text alignment are unchanged, and the mirrored variant is never persisted. | [07-layout-template-system.md](07-layout-template-system.md) |
| NIMA | Neural aesthetic-scoring model (MobileNet backbone) contributing the aesthetic component of QualityScore. | [06-image-analysis.md](06-image-analysis.md) |
| Outside-book tray | The bin holding photos whose date change moved them outside the Book's year (R6); they stay visible so nothing silently disappears. | [09-editor-ux.md](09-editor-ux.md) |
| Page | One printed side, editable singly or as part of a Spread (R8); carries the Pinned/Detached states and its slot→photo placements. | [03-domain-model.md](03-domain-model.md) |
| Page parity | Whether a Page sits on the **Left** or **Right** side of a Spread (even page index = left). Parity is carried as DP state during page partitioning and gates `spreadPair` templates, full-Spread photos, and letting one day's text span a Spread. | [08-auto-layout-engine.md](08-auto-layout-engine.md) |
| PersonTag (people tag) | A named person from OneDrive people tags, pulled via Microsoft Graph and turned into a named top-priority (`person`) Focus Region. | [05-ingestion-and-photo-sources.md](05-ingestion-and-photo-sources.md) |
| Photo | A catalog entry in `photos.json` referencing an immutable original: source ids, date (+ `dateUncertain`), Adjustment Stack, Focus Regions, Tier (+ user override), excluded flag, PersonTags. | [03-domain-model.md](03-domain-model.md) |
| Pinned (page state) | The user touched this Page; "auto-layout rest of chapter" regenerates only unpinned pages and lists the affected page numbers before running (R16). | [03-domain-model.md](03-domain-model.md) |
| Placement | The single stored link between the photo world and the page world: `{ slotId, photoId, crop: CropState }`. A Slot holds at most one Placement and a Photo appears in at most one Placement book-wide; it is both the engine's per-slot output and exactly the record a user's drag/pan/zoom edits. | [03-domain-model.md](03-domain-model.md) |
| Preflight | The gate before PDF export: empty Slots, effective image DPI < 200, text overflow, a non-empty Unplaced bin, and `dateUncertain` photos all block or warn. | [12-pdf-export.md](12-pdf-export.md) |
| Print Profile | A swappable JSON bundle of print-service specifics (bleed, color, spine calculation when covers arrive in v2); the exported PDF itself stays service-generic. | [12-pdf-export.md](12-pdf-export.md) |
| QualityScore | The fused image score (NIMA aesthetic + sharpness + exposure + face count/size bonus), converted to a percentile within the month and then to a Tier (R26). | [06-image-analysis.md](06-image-analysis.md) |
| Safe area | The region 0.375 in inside Trim; text and faces must stay inside it. | [12-pdf-export.md](12-pdf-export.md) |
| `schemaVersion` | The integer that is the first property of every project JSON file's root object (and of every Template file). Additive, defaulted fields do **not** bump it; renames and shape changes do, and ship a forward migration — loaders migrate in memory and never downgrade. | [04-project-format-and-storage.md](04-project-format-and-storage.md) |
| Scrim | The black gradient drawn behind an overlay caption or an overlapping month title so white text stays legible over any photo (R5, R24). Its gradient, height, and padding are `overlayScrim` fields in the Style cascade, not template geometry. | [10-styles-and-typography.md](10-styles-and-typography.md) |
| Section (multi-day) | In a `multiDay` Template, a per-day group of Slots plus text that stays together as a unit, letting 2–3 small days share one page (R28). | [07-layout-template-system.md](07-layout-template-system.md) |
| Seed | The stored integer (in `book.json`) that fixes all engine tie-breaking and variety choices, making re-layout reproducible: same inputs + same Seed = same book. | [08-auto-layout-engine.md](08-auto-layout-engine.md) |
| Single-writer model | The threading rule that every mutation of project state happens on the UI thread through one command pipeline; background jobs compute but never mutate. It is what makes undo, autosave, and determinism tractable. | [02-architecture.md](02-architecture.md) |
| Slot | A placeholder in a Template: an ImageSlot (`rect`, aspect + tolerance, Tier affinity, Caption policy) or a TextSlot (`rect`, role `journal \| caption \| monthTitle`). Rects are normalized [0,1]² over the single-page trim box, origin top-left. | [07-layout-template-system.md](07-layout-template-system.md) |
| Smart-crop | The rule turning Focus Regions into a CropState: choose the maximal crop window of the Slot's aspect that contains the primary Focus Region (highest weight, overlaps merged), then express it as `{zoom, offsetX, offsetY}` (R25). | [08-auto-layout-engine.md](08-auto-layout-engine.md) |
| Spread | A *view* over two facing Pages (22 × 8.5 in trim) — not a stored entity; pages stay independently editable (R8, R22). | [03-domain-model.md](03-domain-model.md) |
| Spread pair | Two `spreadPair`-kind Templates linked by a shared `pairId` (`side: left \| right`) that compose as one facing layout, optionally sharing one photo across the Gutter via matching `spanId` slots (R18, R22). Pairing is a scoring bonus, never a constraint — either side stays independently swappable. | [07-layout-template-system.md](07-layout-template-system.md) |
| Style | Cascading appearance settings (global → chapter → page): image borders on all images, font families/sizes/colors, journal vs caption sizes independently (R23). | [10-styles-and-typography.md](10-styles-and-typography.md) |
| Swap semantics | Dropping a photo onto an occupied ImageSlot swaps the two photos rather than displacing one into a bin — the default drag-drop behavior on pages. | [09-editor-ux.md](09-editor-ux.md) |
| Template | A reusable page layout: stable string id, `pageSize`, kind, ImageSlots, TextSlots, `mirrorable` flag. The v1 library targets ~50 templates with 1–8 photos per page (R20); manual page edits Detach a snapshot rather than mutate the library. | [07-layout-template-system.md](07-layout-template-system.md) |
| Template family | The composition tag every Template declares — `single \| grid \| filmstrip \| hero-rail \| mosaic \| title \| multiday \| spread` — describing its *photo arrangement* independent of where text sits. The engine's variety score penalizes reusing a family on nearby pages, which is what keeps a month from looking like one layout repeated. | [07-layout-template-system.md](07-layout-template-system.md) |
| Template kind | One of `standard \| monthTitle \| fullBleed \| multiDay \| spreadPair` — respectively: everyday layouts, month title pages (R24), edge-to-edge photo pages (R18), multi-day shared pages (R28), and matched left/right pairs (R22). | [07-layout-template-system.md](07-layout-template-system.md) |
| Template linter | The rule set (L1–L13) that validates every library Template at build time — the build fails on any error — and every Detached snapshot in the editor, where issues surface as badges but never block saving. Covers geometry inside trim/bleed/safe, slot overlap, aspect sanity, photo counts, family, and structural integrity. | [07-layout-template-system.md](07-layout-template-system.md) |
| TextSlot | The text-holding kind of Slot: `{ id, rect, role: journal \| caption \| monthTitle, align?, attachedTo? }`. It carries no typography at all — family, size, color, and line height come from the Style cascade (R23) — and `monthTitle` is the one role permitted to overlap an ImageSlot (R24). | [07-layout-template-system.md](07-layout-template-system.md) |
| Thumbnail tiers | The three cached raster sizes: 256 px (grid), 1024 px (layout preview), and full resolution (export only); all regenerable, all rendered through Magick.NET with EXIF orientation applied. | [05-ingestion-and-photo-sources.md](05-ingestion-and-photo-sources.md) |
| Tier | Quality band from the monthly QualityScore percentile: **S** (top 10%), **A** (next 25%), **B** (next 45%), **C** (bottom 20%). Tier drives slot-size affinity; user promote/demote sets it absolutely and it is never re-derived (R26). | [06-image-analysis.md](06-image-analysis.md) |
| Trim | The final cut page size — 11 × 8.5 in landscape by default, with other sizes via template `pageSize` (R19). | [12-pdf-export.md](12-pdf-export.md) |
| U2-Netp | Lightweight salient-object-detection ONNX model producing `saliency` Focus Regions — the lowest-priority kind in fusion. | [06-image-analysis.md](06-image-analysis.md) |
| Unplaced bin | Dockable bin (user's choice of bottom or side) holding photos not placed on any page — fed by template downsizes (R10), drawn from when filling layouts (R12, R13), and the place photos are excluded from the book entirely (R17). | [09-editor-ux.md](09-editor-ux.md) |
| Upcoming bin | Bin view of photos already placed on *later* pages of the current Chapter, so they can be pulled forward onto the current page (R13). | [09-editor-ux.md](09-editor-ux.md) |
| WYSIWYG by construction | The same SkiaSharp draw code renders the screen (`SKElement`) and the PDF (`SKDocument`), so preview and print cannot diverge. | [02-architecture.md](02-architecture.md) |
| YuNet | Fast ONNX face-detection model producing `face` Focus Regions and the face inputs to QualityScore. | [06-image-analysis.md](06-image-analysis.md) |
